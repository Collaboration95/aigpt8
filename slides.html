SayEvery shopping app is one of two screens. A search bar over a recommendation feed — Shopee, Amazon, Coupang — cluttered, predictable, and nobody really engages with the feed. Or the LLM app: an empty screen with a chat box. It asks you to already know what to say.

The idea

Same simple text box. A new screen every time.

3
SayWe keep the one thing everybody already understands: a text box. Nothing to learn, nothing that scares off existing customers. What changes is what comes back. Every request renders a new screen built for that person and that moment, with extra options to explore. You don't lock into one flow, and you won't see the same screen twice.

SayThe live LLM reads the user's order history through lookup tools, then chooses UI tool calls: 23 tools and 127 pre-built visual variants. It never writes UI code. The server checks every product ID and price against the catalogue before anything renders. Below, the learning loop: every tap is a gradient update to the preference model, which re-ranks the next shopping request. Cold start uses the population prior, and one game warms it up.

Assumptions

What we are betting on.

  1. 1Customers already buy repeat items on the platform.Order history is the context. The demo uses 4 seeded orders.
  2. 2A few taps in a game are enough to place a shopper in a segment.Tested on synthetic shoppers: 56.5% correct after 10 taps, against 19.3% for the baseline.
  3. 3People will play a 30-second game while they wait.On the MRT or in a lift, for small coin rewards.
  4. 4An LLM can choose the screen for each request fast enough.First lookup in under 2 s, full screen in 3–4 s.
  5. 5Customers stay in control.Every inference is shown and can be changed.

Demo data: seeded orders, synthetic shopper population, simulated delivery.
