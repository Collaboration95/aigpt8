## Findings and minimum fixes

### P0 — fix before recording the claimed end-to-end story

1. **The post-game shopping task loses its meaning and does not converge to checkout.** Public reproduction: Surprise me → games → new “A small kitchen gift under ₩20,000” → Drinkware → select Milkis. Result is beverages followed by another grid. Local mechanism: `app/llm/retrieve.mjs:5–7` lacks kitchen/gift intent handling; category/budget retrieval depends on `session.goal`. `app/llm/turn.mjs:34` updates that goal only for recognized categories/no-intent text, so Home does not guarantee a new task for the same SID. Selection gets a large ranking bonus but weak-intent completion is not enforced in `app/llm/validate.mjs:26`. Learned ranking is present, but relevance and completion are not. **Fix:** explicit new-conversation/new-goal event while retaining user preferences; enforce current request category and budget; after a concrete choice offer that SKU's checkout; display a grounded learning reason and model run/seq. For this recording, replace the kitchen-gift request with **“Show me snacks under ₩20,000”**, matching observed snack learning and a recognized category. That replacement is a recommendation from source inspection, **not a verified live result from this pass**. Require one targeted acceptance run before putting it on stage; otherwise finish on the dashboard and the already-proven order, without claiming the final purchase bridge worked.

2. **Visible inference correction has incompatible event payloads.** `app/public/kit/context.js:35–37` emits `{forget:"bed"}` / `{change:"bed"}`; `app/public/live.js:49–52` forwards unchanged; `app/llm/validate.mjs:33` requires `{action:"forget",key:"bed"}` / change. Public kit interaction confirmed `Forget King bed · value: {"forget":"bed"}`. Thus a model-generated context button cannot satisfy the server contract; the renderer can even label a fact Forgotten before acceptance. **Fix:** normalize the payload in the live adapter or change the context renderer; update local state only after server acceptance; exercise a real generated Change/Forget followed by the next request. Do not claim tap-to-forget works today. The typed Single-bed correction did work.
