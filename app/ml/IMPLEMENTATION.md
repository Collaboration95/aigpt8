## Shopper segments (25 Oct 2026)

- Added `segments.mjs` alongside the unchanged logistic fit. A separately seeded synthetic behaviour population contains 2,000 users: 1,600 training users and 400 untouched evaluation users. Six k-means clusters use 60-order category/price shares, adjacent-brand repeat rate, repeated-item rate and category diversity. Names and three traits come from centroids. Segment shares and `size_users` describe **training users only**, explicitly identified by `share_basis`; held-out shoppers do not fit clusters, rates, names or priors.
- `GET /api/segments` reports six user bases, their shares and synthetic evaluation. Training-only cluster/archetype matching provides the evaluation label mapping. Ten independently generated Want/Nope exposures per held-out user, with no history supplied, assign **226/400 correctly (56.5%)**, versus **77/400 (19.25%)** for always predicting the most frequent **training** archetype. These are synthetic generator-archetype results, not real customer accuracy or conversion evidence. The test majority differs from the training majority; baseline choice is explicit in `heldout.baseline_method`.
- `GET /api/model?sid=` retains logistic weights/predictions and adds structured `segment:{before,after,top,confidence,evidence_count,game_evidence_count,history_count,confidence_score,normalized_entropy,evidence}`. A new user's prior is cluster shares; Guru's prior additionally incorporates four fixture orders. `before` is this fixed history-only prior. Learned per-item Bernoulli rates are smoothed toward segment category/price rates; observed orders use segment product frequencies. Likelihood powers are 0.4 per game event and 0.35 per historical order. The likelihood spread is scaled, preserving relative odds, to cap each game observation at 0.6 log odds (under 15 percentage points of absolute probability movement).
- Want/Nope uses the observed binary label; Bracket uses a conditional winner likelihood; Budget averages selected-item likelihoods so one basket counts once. Neutral/price-guess events have zero segment effect and do not increase evidence count. Every receipt exposes its product, plain label and per-segment probability shift. Entropy determines confidence, with fewer than six informative game observations always labelled `low`; `high` additionally requires at least 16. This confidence is a concentration score, not a calibrated correctness probability. Undo, retry and journal hydration replay exactly.
- Compact `contextFor` includes top segment + probability/confidence/count. The small `get_preferences` edit in `app/llm/data-tools.mjs` returns the same fields with `synthetic:true`, alongside existing preferences.
